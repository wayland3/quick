**评审模型**：GLM-5（joyparty/coding-zhipu/glm-5）
**评审级别**：L2

**评审轮次**：1
**结论**：PASS（无 BLOCKER）

## 验收确认（评审方逐项核对）

SHGetFileInfo + GetIconInfo/GetDIBits + alpha 掩码重建 + 32×32 PNG ✅；Linux hicolor/pixmaps/绝对路径、XPM/SVG 自然 miss ✅；重建线程内 attach_icons 不碰查询热路径 ✅；缓存存在即复用（计数器验证不再提取）、相对路径 + 出口绝对化 ✅；前端 32×32 contain + ▣/⌘ 回退 + `$APPDATA/icons/**` ✅；UWP 显式置空 ✅；平台 API 边界纯净 ✅；icon_path 列已存在无迁移问题 ✅。

## NONBLOCK（已全部修复）

1. **占位符与图标列宽不一致**（index.css）：`.qw-row-icon` 20px → 32px，消除「有图行 + 占位行」标题左缘参差。
2. **0 字节缓存被当命中**（appindex.rs `ensure_icon_cached`）：Hit 前校验 `metadata().len() > 0`，崩溃残留的坏文件下次重建自愈。
3. **掩码读取失败产出全透明图标**（apps.rs `hicon_to_png`）：掩码 GetDIBits 失败时返回 None（Miss 回退占位），不再编码不可见图标。
4. **首启批量提取阻塞退出**（appindex.rs）：新增 `rebuild_index_with_stop`，`IndexRefresher` 传入停止信号，`attach_icons` 行间轮询提前退出（剩余行置空，下次重建续跑）。
5. **图标文件缺失渲染破图**（LauncherPanel.tsx）：抽 `LauncherIcon` 组件，`onError` 回退占位符号（与 ItemRow 缩略图同模式）。

## 与定稿设计的偏差（已写回设计文档）

- 设计写「PNG/XPM」：实现只认 PNG——XPM 与 SVG 一样无法被 WebView 渲染，缓存无意义。
- 缓存策略明确为「存在即复用不再提取」：启动重建每次都跑，逐个重新提取会拖到秒级；图标滞后到缓存清空才刷新，与系统图标缓存一致。

## 实现备注

- 首次升级后 `icon_path` 语义变化（来源字符串 → 缓存路径）会触发一次 app_index 全量重写，预期行为。
- 孤儿 icons/（应用已卸载）不主动清理：每应用 2–5KB，量小；清空数据目录时随目录消失。

## 遗留

- 真机手测（并入 R-035/R-036）：重建索引后列表显示真实图标；卸载重装应用后图标刷新；`> rebuild` 手动触发后再验证一次。
