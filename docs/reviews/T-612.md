## BLOCKER（已修复）

1. **png_to_dib 产出垂直翻转的 DIB**（platform/imaging.rs）
   - 问题：`wic_decode_bgra` 返回 top-down 行序，`bitmap_info_header` 写正 `biHeight`（bottom-up 语义）后直接拼接未翻转像素。旧函数是无调用方的死代码（旧 `write_image` 对 PNG 条目只写注册 PNG 格式），本任务双格式回写首次激活该路径，PNG 粘贴到读 CF_DIB 的程序（画图等 GDI 应用）会上下颠倒。旧注释「行序翻转为 bottom-up」声明了意图但从未实现。
   - 修复：新增 `flip_rows`（按 stride 首尾配对交换，`split_at_mut` 保证借用安全），拼接前调用；保持正高度（负高度对老 GDI 消费方兼容性差）；顺带补上文档声明的 alpha 统一 0xFF。
   - 验证：新增 1×2 双色非对称方向测试（`dib转png保持上下方向`、`png转dib行序翻转为bottomUp`），删掉 flip_rows 即失败；166 项 cargo test 全绿。
   - 评审确认：第 2 轮逐行核对翻转逻辑、借用安全与测试有效性，PASS。

## NONBLOCK（已随修复顺带完成）

1. **持剪贴板锁做 WIC 转换**（platform/clipboard.rs）→ 重构 `GuardPhase` 两阶段：DIB 字节锁内拷出，转换挪到锁外。
2. **转换后未复检 8MB 上限** → `read_dib_entry` 对 PNG 化结果复检 `IMAGE_MAX_BYTES`，超限走 TooLarge 标记。
3. **SetClipboardData 失败时 HGLOBAL 泄漏** → 新增 `set_clipboard_data_owned`（失败 `GlobalFree`），`write_unicode_text`/`write_html`/`write_rtf`/`set_clipboard_bytes` 四处统一。
4. **测试盲区** → 补 BI_BITFIELDS(40+12) / 8bpp 调色板 / biClrUsed=2 三种 off_bits 断言 + 1×2 方向测试。

## 实现备注

- `image` crate 从 Linux-only 提升为全平台依赖（非新增 crate）：Windows 端 PNG 编码（T-612）与缩略图（T-613）需要，features 仅 png。
- 「图片过大」标记条目的 format 从 `Dib` 改为 `Png`（空数据无 blob，format 仅影响 hash 基；同图旧标记与新标记共存一次，与旧 .dib 条目同属一次性代价）。
