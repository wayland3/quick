# Navicat 划词焦点定位

- 日志中 `WM_COPY` 的目标与顶层窗口相同。`GetFocus` 查询调用线程的输入队列，枚举别的线程的子窗口不会改变查询对象。
- Windows 平台函数通过 `GetGUIThreadInfo` 获取当前前台窗口线程的焦点子控件。服务层在 UIA 前保存窗口和焦点身份，复制前复查。Navicat 的 `TEEAutoCompleteMemo` 使用 `WM_COPY`，其余情况仍用 Ctrl+C。每次只发送一次，避免两种复制先后写入。
- 消息发送限时 100ms。用 Quick 浮层句柄打开剪贴板，持锁复核首次观察到的序列号、所有者 PID 和焦点，再读取和还原。格式写入失败向上返回。来源不明或焦点变化时保留剪贴板。
- 测试覆盖跨窗口、跨进程和无子控件的拒绝条件。Navicat 实测需确认选区预填、原剪贴板还原。

独立评审首轮指出可能双次写入、误判较新的复制及还原失败未报告。改为单次发送、在剪贴板锁内复查、使用有效所有者句柄并报告还原失败后，复评通过。首次观测到序列号之前来自同一进程和同一焦点的写入仍无法区分。

## 热键回调

真机日志记录了目标控件收到 `WM_COPY`，随后热键等待超时，最后后台才拿到 18 个字符。Tauri 的 `window.hwnd()` 会向界面线程派发消息并等待回复。热键回调先保存前台身份，再在后台读取选区并发送原有事件。界面线程随即恢复处理消息。后台读取前后复核原前台。热键派发槽在结果发出后释放，复制回退另持一个槽位直到清理结束。浮层仍由前端处理事件后打开。
